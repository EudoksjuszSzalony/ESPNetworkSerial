# v0.1 Release Checklist

> Status: release-candidate checklist. This is intentionally conservative: unchecked items are the remaining gates before the first public tag.

## Repository and metadata

- [x] Root `library.properties` follows the Arduino library specification.
- [x] Author/maintainer metadata includes the project contact email.
- [x] Repository contains no committed `.exe` files.
- [x] Arduino Library Manager submission lint passes in strict mode with no errors or warnings.
- [x] ESPNS/1 compatibility rules and handshake error identifiers are documented.
- [x] Stable sketch-facing facade and advanced/experimental API boundary are documented.
- [x] Release workflow cross-builds the host monitor and creates SHA-256 checksums.
- [x] Windows installer is built automatically and its integration scripts are covered by CI.

## Hardware and IDE validation

- [x] Native Arduino IDE network Serial Monitor verified on Arduino IDE 2.3.10 / ESP32 core 3.3.10.
- [x] ArduinoOTA and network monitor coexist through upload/reboot.
- [x] Authenticated AES-256-GCM mode verified on real hardware.
- [x] Reset, Wi-Fi disconnect, WIFI_OFF, application stall, and TCP-only fault scenarios exercised on real hardware.
- [x] Install the Windows end-user installer on a normal Windows environment with prior development integration removed and verify:
  - install completes without requiring Go or a repository checkout;
  - the monitor executable is installed under Local AppData and is the binary launched by Arduino IDE;
  - existing unrelated `platform.local.txt` content survives Repair and uninstall;
  - Arduino IDE sees and uses the network monitor after restart;
  - authenticated HMAC-SHA256 + AES-256-GCM mode works after adding `config.json`;
  - UTF-8 BOM in a PowerShell-created `config.json` is accepted;
  - Repair Arduino integration is idempotent and does not duplicate the managed block;
  - uninstall removes only ESPNetworkSerial-managed Arduino blocks;
  - uninstall removes generated `config.json`, `integration-status.txt`, and the empty application directory.

## Arduino Library Manager registration

After the `v0.1.0` tag exists and its release is healthy:

1. Fork `arduino/library-registry`.
2. Add this repository URL to the registry list according to the current submission instructions.
3. Open the pull request.
4. Let the registry automation validate the tagged library.
5. Resolve any registry-bot feedback in this repository, create a new compliant tag if necessary, and update/retrigger the registry submission.
6. After merge/indexing, verify ESPNetworkSerial appears in Arduino Library Manager and installs from the official index.

Repository URL:

~~~text
https://github.com/EudoksjuszSzalony/ESPNetworkSerial
~~~

## Explicitly non-blocking for v0.1

These are useful follow-up improvements but are not required for the first public library tag:

- Authenticode signing of the Windows installer;
- macOS signing/notarization;
- graphical installers for Linux/macOS;
- external cryptographic audit;
- a frozen public multi-transport registration API;
- per-device key provisioning/rotation.

The release must remain clear about these limitations rather than implying they already exist.
